## 五、获奖概率判断

### 5.1 判断依据

1. **赛题是"全流程"导向**，评审会拿六大模块清单逐条对照。本项目六大模块已基本完整（三、六于 2026-11-04 补全），模块一多模态的「公式 LaTeX 还原 + 版面语义」也已于 2026-11-05 晚补齐——功能面已无结构性成段缺失，仅剩启发式边界的**局部扣分**。

#### P1.1 扫描件 OCR：为什么选 RapidOCR（PaddleOCR 路线）而不是 MinerU ✅ 已实现（2026-11-03）

按本节方案完成实现与验证：`Source Tracing.py` 新增 OCR 分支（`_get_ocr` 懒加载、`_run_ocr_lines` 兼容
rapidocr v3/v1 返回结构、`_ocr_page_blocks` 渲染+聚合、`_order_lines_by_columns` 双栏中缝检测、
`_merge_lines_to_blocks` 段落聚合），`app.py` 三处入库入口（单传/批量/远程下载）接入异常处理，
未装引擎时 422 报错直接给出 `pip install rapidocr`。实测：rapidocr 3.10.0 在 Python 3.14 + CPU 可用、
模型随包本地分发；扫描版 Attention 上传被语义查重 409 拦截（相似度 0.9076）；另一份扫描件入库 6 块、
限定提问返回 6 个锚点（全部 `page_num`/`bbox` 合法、阅读序正确）。同时修复了 `index.html`
`drawHighlight` 的 bbox 兜底坐标系错误（原用 `convertToViewportRectangle` 处理 PyMuPDF 顶左坐标会上下镜像，
扫描件无文本层时恰好只能走这条兜底路径）。

**结论：走 PaddleOCR 的技术路线，但用它的 ONNX 轻量发行版 RapidOCR**
（`pip install rapidocr`，v3；旧名 `rapidocr-onnxruntime` 等价，模型即 PP-OCR 检测+识别，
约 15 MB、纯 CPU、完全离线）。**MinerU 不作为本项实现**，理由是它与本项目四个硬约束不匹配：

| # | 本项目的硬约束 | MinerU | RapidOCR |
|---|---|---|---|
| 1 | **下游契约只需要「文本 + 位置框」**：`extract_chunks_from_pdf` 产出 `{text, page_num, bbox}` → Qdrant payload → 前端 pdf.js 按 bbox 画高亮（`Source Tracing.py:86`） | 强项是版面/公式/表格**结构化还原**，产出 Markdown/JSON——但这恰好是本项目原生 PDF 路径也没做的事，为此引入数 GB 模型，收益错位 | 检测框天然带四点坐标，把框聚合成同构 chunk 即可，**锚点、语义去重、References 排除、版本 Diff 全部零改动复用** |
| 2 | **运行环境 = CPython 3.14 + CPU**（`.venv` 为 3.14.7，无 GPU） | 依赖 torch + pdf-extract-kit 权重（数 GB），CPU 推理每页数秒到数十秒；对新版 CPython 的支持偏保守 | 只依赖 `onnxruntime + opencv-python-headless`，对新 Python 版本最宽容；装不上还能退 `rapidocr` 的 openvino 后端 |
| 3 | **答辩演示要离线可跑** | 首次运行需联网下载权重 | 模型随 pip 包本地分发，断网不失效 |
| 4 | **扫描件与原生 PDF 体验要一致** | 输出结构不同，需要额外的格式转换层才接得进现有链路 | 同一条 `{text, page_num, bbox}` 链路，只换文本来源，答辩好讲 |

**实现要点（7 步，约 2–3 天）**：

| 步骤 | 做法 |
|---|---|
| ① 无文本层检测 | `extract_chunks_from_pdf` 内：单页 `page.get_text().strip()` 少于阈值（如 20 字符）判为扫描页；全文提取量过低时整本走 OCR 分支 |
| ② 页面渲染 | PyMuPDF `page.get_pixmap(dpi=200)` 逐页转位图（双栏无需特殊处理，坐标由检测框自带） |
| ③ OCR 识别 | RapidOCR 逐页 det+rec，得到 `(四点框, text, score)`；`score < 0.5` 的框丢弃 |
| ④ 框聚合 | 按纵坐标合并同行、按阅读序拼接（x 坐标阈值分左右栏）；bbox 从图像坐标换算回 PDF 坐标系（注意 y 轴方向与 dpi 缩放） |
| ⑤ 结构对齐 | 产出与 PyMuPDF 路径**完全同构**的 `{text, page_num, bbox}`，ingest / 检索 / 高亮一行不改 |
| ⑥ 优雅降级 | 未安装 rapidocr 时保留现有 422，但报错文案改为给出具体安装命令；`requirements.txt` 增加可选段 `rapidocr` |
| ⑦ 用例验证 | 官方用例 `1706.03762v1_img.pdf`：入库 → 提问超参数细节 → 锚点跳页行级高亮，表现与原生 PDF 一致（这条写进演示视频） |

> **✅ 已于 2026-11-05 晚解决**：未引入 MinerU（四硬约束依旧不匹配），改用 **pix2tex / LaTeX-OCR**（torch CPU 单包约 1GB，为 MinerU 的 1/30；CPython 3.14 实测可装）以**可选依赖**落地视觉层——规则层零依赖保底随 reader 下发，视觉层走独立按需端点（`POST /api/papers/{id}/formula-latex`），**未安装/失败自动回退，主链路零耦合**，完全符合"不与现有止血项绑死"的要求。至此该评估项已关闭。
